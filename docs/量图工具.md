# 量图工具：把画面变成数字

> 为什么需要它：语言模型"看"到的是块状摘要，估不出精确坐标。
> 凡是要准的地方（脸宽、眼位、发际线端点），都必须走程序量，不能凭眼睛。

## 用法

```bash
# 1) 自动找主色（粗，适合第一眼摸底）
python 量图.py 量 图.png

# 2) 指定颜色量（准，日常用这个）
python 量图.py 量 图.png 100 --色 "#d896a9" --色 "#5c4545"

# 3) 比两张图，验证"改一个参数有没有生效"
python 量图.py 比 old.png new.png
```

输出两份：

```
<原名>-量图.png   原图 + 坐标系（每 100px 一根线、带刻度）+ 每种颜色的 bbox 框
<原名>-量图.txt   数字报告
```

报告内容：

```
· 每种颜色的像素数与占比
· 整体 bbox（外接框）+ 质心
· 最大连通块的 bbox（排除零散噪点）——精度 ±4px
· 逐列抽样：在 25%/50%/75% 三处，这个颜色从 y 几到 y 几
```

## 两个模式各自解决什么

| 模式 | 回答的问题 | 典型用法 |
|---|---|---|
| `量` | 这个颜色占哪块、边界在几像素 | 读参考图的结构；确认自己画的形状范围对不对 |
| `比` | 这次改动到底改了什么、改了多少 | 每次只改一个参数后，验证它真的生效了 |

`比` 的经验阈值：

```
几十~几百像素 = 描边/边缘级别的变化（符合预期时）
几千以上     = 形状级别的变化
只有个位数   = 参数基本没起作用，去检查变量有没有真的传进去
```

## 局限（必须先知道）

```
· 颜色聚类是"相近色合并"，JPEG 压缩过的图会把邻近色搅在一起
  → 自动模式只能用来摸底，正式量要 --色 指定具体颜色
· 连通块是降采样后算的，精度 ±4px
  → 要像素级精确，就缩小 --降 或直接看逐列数据
· 它不判断"好不好看"，只给数字
```

## 更好的替代方案（如果你有条件装）

### 代码库

```
scipy.ndimage.label            连通块的正规做法，比这里手写的快几十倍、且精确
scipy.ndimage.find_objects     一次拿到所有连通块的外接框
cv2.findContours + minAreaRect 轮廓、外接旋转矩形、凸包
cv2.HoughCircles               找圆（眼睛、宝石这类）
cv2.matchTemplate              模板匹配（找"同样的眼睛"出现在哪）
skimage.measure.regionprops    形状统计（面积、长宽比、主轴方向）——读头发走向特别好用
```

本工具没有依赖它们（环境里没装），所以用 numpy 手写了降采样连通块。
**如果你能装 scipy，直接把 `最大块()` 换掉，精度和速度都会上去。**

### 现成软件（人用）

```
ImageJ / Fiji    科研级测距、角度、面积；能做比例尺校准（推荐）
GIMP             有网格和标尺，可以手动量
Aseprite         像素画专用，能直接读每个像素的值和坐标
Krita            网格 + 参考线，适合描图
```

### 视觉路线（不用装东西）

```
① 把图分块放大再看：整图缩略看不出细节，切 4~9 块各放大 2 倍给我看，比我猜准
② 直接让人类给坐标：最快最准，一句话省一轮迭代
③ 转成"字符画"看形状：把图渲染成 ░▒▓█ 网格，形状走向反而更清楚（细节会丢）
```

## 和"从头画"的关系

量图只解决**读**，不解决**判断**。正确顺序是：

```
量（本工具）→ 把数字写成参数 → 出图 → 人判"对不对" → 只改一个参数 → 再量/再比
```

这也是 `docs/从零画一张脸.md` 里反复强调的那条循环。
