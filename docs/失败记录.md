# 失败记录

这份文档只记**真的发生过**的错误：怎么发现的、错在哪、怎么改的。不是"注意事项"，是病例。

写它的理由：教程里"应该怎么做"看一眼就忘，"当时怎么翻车的"能记一辈子。

## 一、整张图发蓝（PIL 的颜色是 BGR）

**现象**：画完出图，脸是蓝的。人类回了一句"外星人"。

**原因**：

```python
肤 = (0xf8f2ee)          # 这不是三元组，是一个 int
d.polygon(点们, fill=肤)  # PIL 把 int 当 0xBBGGRR 解析
```

一个 int 传给 PIL，它按 BGR 拆字节：`0xf8f2ee` → B=0xf8, G=0xf2, R=0xee，于是脸变成蓝色。

**改法**：所有颜色走一个转换函数，写 `色(0xf8f2ee)`，返回值是 `(r, g, b)`。

```python
def 色(v):
    return ((v >> 16) & 255, (v >> 8) & 255, v & 255)
```

**教训**：颜色是三元组还是整数，PIL 不会报错，只会画错。这类"静默错误"必须靠肉眼或量图抓。

## 二、下层凭空消失（整图 paste / 纯白当背景）

**现象**：垫底片、侧发画完就没了；或者眼睛叠上去以后眼白被填成一整块肤色。

**两个不同的原因，表现一样**：

```
① 用一张不透明（白底）的整图 paste 上去了 —— 它把下面所有层盖住
② 判断"背景"用的是"接近纯白" —— 眼白也是纯白，于是眼白被当成背景重画
```

**改法**：

```
① 一律用掩码落色：先算 bool 掩码，再把颜色填进掩码内，绝不 paste 整图
② 背景判定不能只看颜色，要加位置条件：
   纯白 & 不在脸轮廓内
```

**教训**：图层问题看起来像"没画"，其实是被盖住了。排查顺序永远是：先看图层顺序，再看掩码。

## 三、眼睛偏了 1 像素（numpy 圆 vs PIL 椭圆）

**现象**：右眼的虹膜比眼白往右错一格，放大后很明显。

**原因**：眼白用 `ImageDraw.ellipse` 画，虹膜用 numpy 的圆判定 `(x-cx)²+(y-cy)² ≤ r²` 画。两种栅格化在边界上的取舍不同，差 1 像素。

**改法**：虹膜也用 PIL 画进一张 L 掩码，再拿掩码落色；两处用同一个 API。

**教训**：同一个几何形状，别用两套方法栅格化。混用就会错格。

## 四、垫底片切在"刘海最宽行"还能看见

**现象**：垫底片按"刘海最宽的那一行的 y"切底，结果从缝里露出来。

**原因**：刘海是斜的，最宽行 ≠ 最低点。按最宽行切，两侧还露在外面。

**改法**：逐列取上层（刘海）在该列的最大 y，作为垫底片该列的底边；宽度取到侧发中线；再和头顶圆取交。

**教训**："按一行切"是二维思维用在一维形状上。斜的东西必须逐列处理。

## 五、想要"分束"，结果被闭运算抹平

**现象**：头发内部有几条细线（分束感），人类嫌"脏"，让我清。我用闭运算（膨胀 3 次再收缩 3 次）填平凹口，线没了——**分束也一起没了，整块变成一坨**。

**原因**：闭运算填掉所有小于约 6 像素的凹口，而分束感正好来自这些凹口。

**改法**：

```
只清"内部"的描边：把整块往内收 3 像素，落在内部的线全删，外轮廓保留
想要分束就另外画 1 像素细线（比描边浅一档），不靠轮廓
```

**教训**：轮廓上的每个凹口都可能是"有用的细节"。批量修补前先问：这个东西是不是我想要的？

## 六、透明导出把高光抠掉了

**现象**：导 8 倍透明版给人类，他回"高光又没了"。

**原因**：导出时把所有纯白像素设成透明，而眼睛里那个高光就是纯白。

**改法**：只从四角泛洪选"连通的背景"，内部的白不动。

```python
背景 = 四个角分别魔棒泛洪取并集
alpha = 0 where 背景 else 255
```

**教训**：抠图必须按"连通性"，不能按颜色值。纯白、纯黑、纯透明这类极值最容易误伤。

## 七、把"跟着人"当成"站着不动"来量地形

**现象**：地形扫描结果全是同一个值（起伏 0.00），结论全错。

**原因**：机器人开着"跟随主人"，我把它传送到采样点，它自己走回去了；量到的是它落脚那一格的地面。

**改法**：采样前先停跟随，采完再恢复。

**教训**：测量前先确认"被测对象此刻在受谁控制"。
